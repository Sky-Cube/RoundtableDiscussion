## 编号与术语

| 记号 | 本文含义 |
| --- | --- |
| `P01–P12` | 开发任务。P01–P02 定规格，P03–P04 实现前端，P05–P08 实现后端，P09–P12 验证和交付。 |
| `R01–R08` | 应用实际调用的模型任务。依次为阵容、报名、专家发言、结论提炼、主持开场、主持介入、总结、有限修正。执行次序由后端根据场景决定。 |
| `U01–U04`、`F01–F07`、`N01–N03` | 用户痛点、产品功能、非功能要求。具体含义均见下方项目规格摘要。 |
| `T01–T08`、`E01–E07`、`Q01–Q04` | 单元与集成测试、浏览器端到端测试、模型语义质量评估。编号后首次出现时给出可执行目标。 |
| SDD、DDD、TDD、E2E | 本项目分别用规格驱动开发确定数据和接口，以设计驱动开发落实前端视觉与交互，用测试驱动开发实现核心后端逻辑，再用端到端测试验证整条用户流程。 |
| Red、Green | Red 先证实目标业务断言失败。Green 实现功能后用同一用例证明通过。无法构建或启动是运行故障，须记录并处理后再验证目标断言。 |
| API、SSE、JSON Schema | API 是应用接口。SSE 是服务端向浏览器推送事件的长连接。JSON Schema 是约束 JSON 字段、类型和取值的机器可读契约。 |
| 测试数据、模型网关替身 | 测试数据提供固定输入与预期。模型网关替身返回事先编写的响应或故障，用于验证服务端逻辑，不代表真实模型已完成分类或生成。 |

## 项目规格摘要

AI Panel Studio 是本地单实例的中文 Web 应用。用户提交议题、预览专家阵容、确认开场，也可旁观已有活动房间。面向希望在短时间内看清选项与争议的产品决策人员、研究人员和内容创作者。主体开发使用同一款 Vibe Coding 工具，按 SDD、DDD、TDD、E2E 逐步交付。

| 编号 | 用户痛点与解决路径 |
| --- | --- |
| U01 | 多个角色得出同一种结论，用户无法比较决策。阵容提供不同取舍，主持追问会改变选择的条件。对应 F02/F03、R01/R05/R06、Q01。 |
| U02 | 各角色独立答题，观点之间没有交互。每位专家基于同一版实录报名，补充或反驳关联原发言。对应 F03/F06、R02/R03、Q02。 |
| U03 | 只见最终答案，看不到观点如何变化。公开真实小窗状态、发言实录和带证据的直播结论。对应 F04–F07、R04/R07、Q03/Q04。 |
| U04 | 多个议题混用上下文，切房或重连后串场。服务按房间隔离输入、存储、事件与前端会话。对应 F01/N02、T06、E02/E04。 |

| 编号 | 功能或非功能规格 |
| --- | --- |
| F01 | 大厅列出进行中的房间，支持新建、旁观和从样例生成草稿。旁观使用既有房间。 |
| F02 | 识别评估、提案、排查或探索目标，创建 1 位主持加指定人数的专家。默认 4 位，范围 2–6 位。展示讨论目标、姓名、职业、职称、色标，以及专家的立场和视角。确认后才开始。 |
| F03 | 主持界定范围、追问多方证据、厘清分歧并串联阶段，收尾只归纳专家发言。后端按讨论目标配置阶段与报名窗口。专家在每个窗口独立报名，服务端裁决，允许同人连发。专家每次 1–2 句。 |
| F04 | 小窗展示 `IDLE/PREPARING/SPEAKING` 与受控公开关注点。公开页面不显示报名原始数据或模型隐藏推理。 |
| F05 | 每条专家发言提交后尝试提炼共识及分歧，至少两位本场专家的真实引文支持一条结论。证据不足可为空，提炼失败显示暂缓并保留上次有效结果。 |
| F06 | 实录显示发言人、职业、职称、色标及纯文本正文，按场内发言序号排序并支持引用跳转。 |
| F07 | 自然语言主持总结提交后进入完成状态。失败保留已公开实录。 |
| N01 | Vue 3 + TypeScript + Vite、Java 21 + Spring Boot、SQLite，前后端独立启动。上游凭据从后端环境变量读取，预设至少 5 条且可重复初始化。 |
| N02 | 支持至少两场同时执行。房间状态、实录、投影和 SSE 都隔离，支持断线重连及历史回放。 |
| N03 | 中文响应式界面，验收视口 1920×1080、1366×768、390×844。内容区内部滚动，移动端可切换直播、嘉宾与结论。 |

最小状态契约为 `DRAFT → RUNNING → SUMMARIZING → COMPLETED`，执行或总结失败进入 `FAILED`。同一草稿只能成功启动一次，终态仍可读取。首版话题长度为 3–120 个 Unicode 码点。数据库至少维护房间、成员、发言、结论、证据、公开事件及预设。成员、发言及证据采用含讨论 ID 的复合键约束，业务记录与公开事件同事务提交。

`DRAFT` 是等待确认的草稿，`RUNNING` 是正在讨论，`SUMMARIZING` 是正在生成总结，`COMPLETED` 和 `FAILED` 是完成及失败终态。`PASS` 表示专家主动跳过本次报名。`PENDING`、`FRESH`、`STALE` 分别表示尚未提炼、当前提炼成功、提炼暂缓并保留上次有效结果。结论来源游标记录已成功处理的最新专家发言号，SSE 游标记录本场已提交的公开事件号。

HTTP 基路径 `/api/v1`，一般响应为 `{code,message,data,timestamp}`。七个入口是 `GET /discussions?status=ACTIVE`、`POST /discussions`、`GET /presets`、`POST /presets/{slug}/discussions`、`POST /discussions/{id}/start`、`GET /discussions/{id}` 和 `GET /discussions/{id}/events?after=<seq>`。创建接受 `{topic,expertCount?}`。详情含房间状态、参会者、发言、结论及 `lastEventSeq`。事件字段、来源和应用顺序见本文模型、服务端与 SSE 字段归属。

| HTTP 与业务码 | 业务含义 |
| --- | --- |
| `400`、`403`、`404` | 参数无效、来源被拒绝、格式合法的资源标识找不到记录。 |
| `409`、`429`、`500` | 状态冲突、容量已满、本地存储或系统故障。 |
| `502`、`503`、`504` | 上游模型调用或输出校验失败、模型配置缺失、上游模型超时。 |

| 编号 | 测试目标及最小断言 |
| --- | --- |
| T01 | 目标分类、阵容人数、角色、视角、语义重复和失败回滚。 |
| T02 | 类型阶段配额、同轮快照一致、裁决不随回包顺序改变、允许连发、区分全员 `PASS` 与整轮失败。 |
| T03 | 拒绝非法回应、越界句数、隐藏字段，失败恢复小窗状态。 |
| T04 | 结论可在直播中更新，重复说话者与假引文被拒，失败保留旧投影。 |
| T05 | 重复确认只开一场，两场并行，任务超时释放并发槽位。 |
| T06 | 业务与事件原子提交，按房间回放，断流或回滚后状态正确。 |
| T07 | 主持顺序、追问次数和总结资源预留，只有有效总结成功落库才完成。 |
| T08 | Schema、输入安全、修正次数、预算截断、房间快照版本和错误映射。 |
| E01 | 从创建到总结，确认前不开场，检查专家连发与引用定位。 |
| E02 | 两个房间并行，从大厅旁观已有房间，数据互不串场。 |
| E03 | 直播中看到专家状态及结论，提炼暂缓保留旧结论，恢复后更新。 |
| E04 | 断线期间后端继续，重连无漏项和重复，切房丢弃迟到事件。 |
| E05 | 容量和模型故障可恢复，拒绝未授权 Origin，检查网络、构建、日志中无密钥。 |
| E06 | 三种视口独立滚动，支持键盘和窄屏标签切换。 |
| E07 | 五条预设幂等初始化，重复复制产生两个独立草稿。 |

交付含完整源码、SQLite 初始化及样例、Markdown/Mermaid 开发文档、API 文档、README 和测试。提交用 Prompt 文档收录至少 5 段实际发送内容并覆盖四阶段，工作流说明按作业要求记录真实工具、模型和解决过程。

## 每轮执行与交付规则

```text
你协助开发本地中文 Web 应用 AI Panel Studio。遵守仓库 AGENTS.md。
使用 Vue 3、TypeScript、Vue Router、Vite 和 EventSource，后端使用 Java 21、Spring Boot、Spring MVC、Spring JDBC 和 SQLite。项目凭据由后端环境变量读取，新增注释用中文。针对本轮回报实际用到的版本。
先列出交付文件和验收用例。已有仓库时，以实际代码、冻结接口和测试为依据。只有本文件时，依据本文对产品范围、接口、枚举和错误码的说明开展当前任务。涉及已有产物的断言等文件可用后再运行，报告中标明缺失的输入。

SQLite 隔离适用于所有开发、初始化、迁移演练、查询、故障注入和验收。禁止打开项目业务库，包括只读、复制、导出和模式检查。只允许使用本轮新建的空白内存库或专用临时文件库。启动或获取 JDBC 连接前，为测试显式注入独立数据源，解析绝对路径、符号链接和目录联接，核对目标位于本次新建的测试目录。忽略指向现有库的业务配置、环境变量和默认回退。路径或配置无法保证隔离时，停止该数据库用例并记录原因。用 init.sql 初始化空测试库，多连接、事务回滚和 SSE 联调使用临时文件库。每条连接核对外键约束已启用。

按当前阶段的计划运行全部可独立执行的必测用例。单个断言失败后继续其他独立用例，依赖该失败步骤的用例记录为未运行。发现数据源越界、会接触业务库或无法安全隔离时，立即停止相关操作，其他无关检查可继续。测试驱动任务分别执行 Red 与 Green，Red 记录预期的业务断言失败，Green 重跑同一批用例。保留正常退出或非零退出的实际结果。只有必交产物齐全且全部必测验收通过，阶段才通过。存在失败或必测未运行时，列出实际原因及受影响用例。

每轮写 docs/evidence/<阶段>.md，保留该阶段原有记录，追加本次结果。正文包括本轮范围、代码及测试文件、已核验环境、实际命令和退出码、逐用例结果、产物位置及剩余缺口。有 Git 元数据时记录基线和提交。逐用例按下面的报告表填写。本阶段没有数据库操作时，数据库证据填“不涉及”。
脱敏后的 stdout/stderr 与测试框架诊断写入 test-results/prompt/<阶段>/<运行标识>/<red|green|checks>.log。报告只引用日志路径、失败断言和关键证据；失败用例另存 test-results/prompt/<阶段>/<运行标识>/<用例ID>.json，包含测试请求、测试模型响应或 HTTP 响应、关键 SQL 查询及查询结果。仅对可复现的合成测试数据保留完整请求与响应。真实模型或外部输入只保留脱敏片段和错误码。移除凭据、Authorization、Cookie、用户个人数据及原始推理内容后才写入文件。相关证据路径须能从报告定位。

测试结束后关闭数据库连接和测试进程，清理本次创建的临时库以及 WAL、SHM、journal 文件。默认成功和失败都清理，失败优先保留合成输入与查询结果。需要留库复现时，由显式的测试调试选项开启，仅保留本次生成的合成失败库，记录准确路径和手动清理命令。临时库、日志和调试包不纳入提交或应用发布包。
```

复盘说明。一开始是想把测试只能用临时库、失败要留下记录这些规矩一次说清楚，后面每轮就不用重复交代。中途发现本机以前留下的数据库会让测试结果不准，所以补上了不许碰正式库、越界就停的硬性要求。

### 验收报告格式

报告第一段写 **阶段、运行标识、运行日期、变更文件及总结果**。命令段逐条记录工作目录、完整命令、退出码和日志路径。`预期` 必须含能判断成败的字段或业务条件。`实际` 写观测值。需要 SQLite 证据时，写出数据库模式、查询条件、基线值和结果值。失败样例使用相同用例 ID 定位。

| 用例 ID | 阶段 | 预期 | 实际结果 | 结果 | SQLite 证据 | 复现命令与证据路径 |
| --- | --- | --- | --- | --- | --- | --- |
| `P05-ROLLBACK-MEMBER` | `Red` 或 `Green` | 成员写入失败后，房间、成员、事件的新增记录均为 `0` | 填写三张表各自基线、事务后行数及异常 | `PASS`、`FAIL` 或 `未运行` | 填新连接查到的三张表结果及作用范围 | 填实际命令、脱敏日志和失败样例路径 |

在测试失败且失败符合预期断言时，Red 验证成立，测试本身仍记 `FAIL`。阶段通过以 Green 和相关回归的实际结果判断。`未运行` 填缺失前置条件。模拟模型的测试通过只说明业务逻辑通过，真实模型结果另报。

失败样例文件使用以下字段。无对应数据时填 `null` 或空数组。命令的 stdout、stderr 和堆栈留在脱敏日志里，Markdown 报告只保留能复核的关键结果。

```json
{
  "caseId": "P05-ROLLBACK-MEMBER",
  "testPhase": "Green",
  "request": null,
  "modelResponses": [],
  "httpResponse": null,
  "failedAssertion": null,
  "sqliteQueries": [],
  "databaseArtifact": null
}
```

`request` 记录方法、路径及脱敏请求体。`modelResponses` 按实际调用次序记录测试响应。`httpResponse` 记录状态和脱敏响应体。`failedAssertion` 记录预期、实际与断言位置。`sqliteQueries` 记录语句、绑定参数、基线和结果。`databaseArtifact` 记录显式留存的合成失败库路径和清理命令。

## P01｜SDD 数据建模和状态机

```text
以本文的项目规格摘要为基线。交付 docs/PRD.md 产品需求文档与 docs/schema.md 数据规格。分别说明视角单一、讨论割裂、过程不可见、房间串场这四类问题如何解决和验收。标出模型负责的生成任务及应用负责的固定规则。
数据规格包含 Mermaid 实体关系图、状态机、字段与约束、事务内写事件、数据库迁移和五条幂等预设。持久化四类 discussionGoal，定义旧记录的 EXPLORE 回填。说明房间归属、证据来源序号、暂缓保留旧投影、重复确认与失败回滚。用独立测试库验证拟交付的 SQL。
完成标准是每条数据或状态约束都有负责组件、输入及可预期的通过和拒绝结果。按共用规则运行可执行检查并报告依赖、命令、结果与缺口。
```

复盘说明。先把房间怎么归属、什么时候算结束、哪些数据必须一起写入定下来，后面写测试才有准头。刚开始担心这些规则只写在文档里没人管，所以要求每条规则都写清楚由哪段代码负责、什么情况该拒绝。

## P02｜SDD 冻结 API 与 SSE 契约

```text
交付 docs/api.md、可机器校验的公开接口契约与联调样例。按本文列出的七个入口定义请求、响应、空值、HTTP 状态和业务码。若已有数据规格，用其中的持久化状态核对响应字段。列出讨论目标、成员视角、回应发言号、结论更新状态和结论来源游标的取值。草稿与详情返回固定讨论目标，阶段和报名窗口由后端保管。
给出每个 SSE 事件完整 JSON 示例和时序，逐一推演快照间隙、Last-Event-ID 优先级、重复事件、错误游标、换房、订阅容量与终态。使用 A/B 房间及两个客户端，证明事件顺序可复现。
逐事件列出模型候选来源、服务端生成字段及前端应用条件。验证模型附带 roomId、status、时间或游标时不能进入事件，客户端只消费已提交事件。
完成标准是七个入口及四种公开事件均有结构检查及正常、拒绝样例，并给出两房间的提交、回放与失败预期。运行契约校验，按共用规则记录结果和未验证行为。
```

复盘说明。想在前端和后端动手之前，先把接口长什么样、断线后怎么接着收消息定死，免得两边各做一套。最容易扯不清的是重连时从哪条消息开始补、讨论结束后连接怎么收尾，所以让 AI 把每种消息里谁生成哪些字段都列清楚，并强调模型自己带的信息不能直接拿来用。

## P03｜DDD 大厅与阵容组件

## 一、后端内部模块划分（必须实现，模块边界明确）

2. 请求 DTO：

> 模拟内容拦截：直接丢弃，不进入补偿流程；返回 502。
> 全部失败场景断言：数据库无新增 discussion、participant 记录。

5. **P05‑SEMANTICS（Q01 低质量阵容校验）**

> 
> topic：`采购还是自研 AI 客服`。
> 脚本网关替身返回：两位专家拥有合法互不重复 perspective，但是两者 stance 完全相同：`"先小范围试点，指标达标后再扩大推广"`。
> 补偿配置：允许最多一次 R08 补偿；第一次输出低质量，补偿修正输出仍然同样低质量阵容。
> 预期：触发 LOW_QUALITY；拒绝创建草稿；HTTP 502，code=502，`data=null`。
> 统计：**一次 HTTP 创建请求 → R01 初次调用 1 次 + R08 补偿调用 1 次，上游模型总调用 = 2 次**。
> 后端不存储用户输入；由前端保留 topic、expertCount，提供手动重试、预设复制入口；只有用户主动发起复制预设请求才调用复制接口。
> 注意：本用例验证完全相同 stance；近义语义判断不属于 P05，放到后续独立样本评估。

6. **P05‑ROLLBACK‑MEMBER**

> 
> ① 业务事务故障：合法 rosterOutput 进入创建事务；在 discussion 行已写入、至少一条 participant 写入之后，触发测试环境专属故障注入抛出异常。
> 新数据库连接查询断言：该房间 ID 对应的 discussion、participant、discussion_event 新增行数全部 = 0；其余基线数据不变。正常 DRAFT 草稿创建**不写入任何 discussion_event 记录，lastEventSeq=0**。
> ② 额外测试：事务内先写入一条合成 discussion_event，再抛出异常；验证三张表全部回滚无新增。
> 生产环境普通草稿禁止写入事件；故障注入仅 test profile 生效。
> 故障映射 HTTP 500，`data=null`。

7. **P05‑PRESET‑VALID**

> 
> 空测试库执行两次初始化脚本；断言预设数量不变，预设内容不变。
> 对同一个合法 slug 连续两次复制预设；得到两条不同房间 ID，两套不同成员 ID；discussionGoal、topic、expertCount、所有专家 stance/perspective 完全一致；**模型网关调用计数 = 0**；两条记录 status=DRAFT，`lastEventSeq=0`。

8. **P05‑PRESET‑INVALID** 三类负用例

> 
> 1）slug 格式非法：`Bad_Preset`大写 / 下划线，返回 400。
> 2）slug 格式合法但是不存在：`not‑found‑preset`返回 404。
> 3）存在但是损坏预设：缺少 HOST 主持、非法 role 角色、专家 perspective 重复。使用 mock 预设仓储替身注入损坏预设记录；读取 / 复制接口返回 500。
> 全部负例断言：discussion、participant、discussion_event 无任何新增行；不返回半组成员 / 半草稿。
> 保留数据库层面约束断言；优先应用服务层校验，再验证数据库约束拒绝坏写入。
