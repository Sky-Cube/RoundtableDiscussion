# P12 缺陷修复记录：E2E 验证到过期可执行产物

> 范围说明：本轮 E2E 没有发现需要修改产品代码的缺陷；闭环修复对象是「验收证据本身失效」这一测试基础设施缺陷，符合 P12「只修复一个已观察到的问题」的约束。

## 1. 现象

- run5 全量 E2E 显示 5/5 通过，但 `backend-app.log` 记录 `presets=5`。
- 当前 `init.sql` 已包含 6 条预设，源码中的 E07 断言也应覆盖 6 条。
- 即：**用例通过，但验证的是旧 jar 的旧行为**，结论不可用于交付验收。

## 2. 根因

- Playwright `webServer` 直接执行 `java -jar backend/target/ai-panel-backend-exec.jar`，`run.mjs` 不检查 jar 与 `backend/src` 的时间关系。
- 只要本地存在历史构建产物，测试就会静默复用，预设数量、接口行为都可能与当前源码不一致。
- 直接触发点：上一轮构建早于 `init.sql` 新增第 6 条预设，jar 内仍是 5 条种子数据。

## 3. 修复

1. `frontend/tests/system/run.mjs` 新增守卫：递归取 `backend/src/main` 最新 mtime，若 jar 缺失或早于源码，直接以明确错误中止：
   - 「缺少后端可执行 jar，请先执行 mvn -B package -DskipTests」
   - 「后端 jar 早于源码修改，请先执行 mvn -B package -DskipTests 再运行 E2E」
2. E07 预设断言改为与接口返回一致（`length >= 5`、slug 唯一、条数与大厅卡片一致），避免把种子数量写死。

## 4. 验证

| 步骤 | 结果 |
| --- | --- |
| `mvn -B package -DskipTests` | BUILD SUCCESS，jar 15:27:46 |
| run6 | 守卫通过，`presets=6`；4/5 通过，E07 因大厅卡片异步渲染读到 0 失败 |
| E07 断言改为 `toHaveCount` 自动重试 | 类型检查通过 |
| run7 | **5/5 通过，1.6m / 2.3m / 2.1s / 1.4m / 1.6s，`presets=6`** |

证据：`test-results/prompt/P10/20261121-e2e-run7/playwright.json`、`backend-app.log`；失败对照 `20261121-e2e-run6-console.log`。

## 5. 影响与遗留

- 仅改动测试资产（`run.mjs`、`system.spec.ts`），无产品代码变更。
- 后续任何 E2E 运行都必须先打包，否则会被守卫阻断，避免再次产出失效证据。
- 另一个已观察问题（本机残留 `backend/data/panel.db` 导致 `P05DbIsolationIT` 断言失败）属环境残留，已将该文件改名备份，后端 121 项测试恢复全绿，未做代码改动。
