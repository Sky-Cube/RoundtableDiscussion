基础设施层面的缺陷与处理：

1. `globalSetup` 启动的 java/vite 在测试开始前被回收 → 改用 Playwright `webServer` 托管三进程。
2. `outputDir` 与 HTML 报告目录重叠报错 → `outputDir=<run>/artifacts`，HTML 放 `<run>/html`。
3. E2E 直接复用预构建 jar，曾验证到过期产物 → `run.mjs` 新增「jar 早于源码即中止」守卫。
4. 本机残留 `backend/data/panel.db` 导致后端 `P05DbIsolationIT` 失败 → 已改名备份，测试恢复全绿（详见 P11）。

质量抽样（run7b，`real-model-report.json`）：

- 主持开场明确议题与验收标准，`stance/perspective` 均为 `null`。
- 3 条专家发言均回应前序发言（`replyTo` 指向 1/2/2），长度 130–160 字，无跑题。
- 1 条 `CONSENSUS` 结论，证据 `[2,4]` 覆盖两位不同专家，全部可在实录中回查，状态 `FRESH`。
- 失败后房间仍可回看已公开实录与结论，符合「失败后可回看」要求。

结论：真实上游在本机链路上的单次延迟普遍超过 10s 超时阈值，导致 R01/报名窗口失败；因此自动化 E2E 必须使用可控替身，真实模型只做抽样记录。这是**上游时延约束**，不是 E2E 用例失败。

## 5. 未覆盖与风险

- 自动化环境通过 `--disable-webgl` + `reducedMotion` 关闭 WebGL 场景渲染，只验证 DOM 布局与滚动；WebGL 首帧与降级（`data-renderer="flat"`）未被三视口断言覆盖。
- `workers=1` 串行执行，未做多浏览器并行压力；两场并行由同一浏览器的两个 context 模拟。
- 容量槽位在终态提交后才释放，终态瞬间重试仍可能收到 429；用例以轮询重试兜底，属产品时序特性而非缺陷。
- 替身模型延迟固定，未模拟 10s 级慢上游；慢上游行为由第 4 节真实模型记录补充。
