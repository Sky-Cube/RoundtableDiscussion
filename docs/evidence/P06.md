# P06 确认开场与讨论编排验收

运行标识 `20261120-p06`，日期 2026-11-20。在 P05 基础上补齐 `POST /discussions/{id}/start`、讨论执行编排、席位状态事件与执行容量控制，使房间能真正从 `DRAFT` 走到 `COMPLETED` 并产出实录、结论与公开事件。总结果为通过：后端全量 **76 项**测试（1 项跳过）通过，前端 29 项组件测试与 6 项浏览器测试通过，真实 HTTP 与浏览器联调均观察到完整讨论。

## 行为

1. `POST /api/v1/discussions/{id}/start` 用条件更新 `DRAFT → RUNNING`，同一草稿并发确认只有一个获胜者；已运行返回 `202` 与当前状态，终态返回 `409/B0003`，容量已满返回 `429/B0004` 且保留草稿。
2. 编排按「主持开场 → 5 条专家发言（非座位顺序的确定性议程）→ 第 3 条后主持追问 → 第 2、4 条发言后实时结论 → 收尾」推进；每条席位状态、发言与公开事件在同一事务提交。
3. 席位状态只发 `IDLE / PREPARING / SPEAKING`，`publicFocus` 取自受控视角映射，`IDLE` 时清空。
4. 执行槽位先占用再落库，线程池容量 2；无槽位或提交异常时回滚状态并返回 429。
5. 任何执行异常把房间置为 `FAILED`、复位全部席位并发布失败事件，已提交内容保留。
6. 生产 profile 没有真实模型，`PlaceholderDebateWriter` 直接按缺配置处理；`dev` 使用确定性脚本写手，不代表模型质量（P08 替换）。

## 缺口

- 阶段配额、报名（R02）与主持介入的条件化触发仍是固定脚本流程，未实现按讨论目标区分的阶段序列（P08 及后续）。
- 进程重启时未收尾房间的自动 `FAILED` 恢复尚未接入启动钩子。
- 真实模型未接入，`ScriptedDebateWriter` 只用于本地演示。
