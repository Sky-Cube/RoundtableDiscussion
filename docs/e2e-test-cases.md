# E2E 测试用例（系统级）

本文档描述 AI 圆桌演播厅的系统级 E2E 用例设计，执行脚本位于 `frontend/tests/system/`。用例直接驱动真实浏览器、真实 Spring 后端与临时 SQLite，模型上游使用受控替身，避免随机内容影响断言。

## 1. 测试环境与约束

| 项目 | 取值 |
| --- | --- |
| 前端 | Vue 3 + Vite 开发服务器，`127.0.0.1:5299` |
| 后端 | `ai-panel-backend-exec.jar`，`127.0.0.1:18081` |
| 模型上游 | 受控替身 `tests/system/support/fake-upstream.mjs`，`127.0.0.1:18082` |
| 数据库 | 每轮运行创建空白临时 SQLite，结束后删除 |
| 浏览器 | 系统 Chrome（Playwright `channel: chrome`），无头模式 |
| 并发 | 单 worker 顺序执行，用例内部按需创建独立浏览器上下文 |
| 证据 | `test-results/prompt/P10/<runId>/`，含 Playwright JSON 报告、截图与四类进程日志 |

启动命令：

```powershell
cd frontend
$env:SYSTEM_RUN_ID="20261121-e2e-run7"
npm run test:system
```

## 3. 用例明细

### E01 主链路

- **前置**：空白临时库、模型替身可用。
- **步骤**：
  1. 大厅填写议题「系统甲场：客服机器人上线前的验证条件」，选择 2 位专家，生成阵容。
  2. 断言创建返回 201、进入阵容预览、快照为 `DRAFT`、无实录、`lastEventSeq=0`。
  3. 点击「开始讨论」，进入演播厅。
  4. 观察主持人开场先于专家发言；成员状态出现 `PREPARING` 或 `SPEAKING`；小窗仅一条当前发言。
  5. 等待结论面板出现引用按钮，此时房间仍为 `RUNNING` 或 `SUMMARIZING`。
  6. 点击证据按钮，断言对应实录条目获得焦点。
  7. 等待 `COMPLETED`，断言总结非空、弹窗展示入库总结。
  8. 读取 SSE 回放，断言序号 1..N 连续、`SUMMARY` 事件早于终态事件。
- **预期**：全链路无人工干预；结论可追溯；终态晚于总结入库。
- **反例约束**：确认前不得出现任何实录或事件；未完成总结不得置为 `COMPLETED`。

### E02 并行与旁观

- **步骤**：
  1. 两个独立上下文分别创建「系统乙场」「系统丙场」并启动。
  2. 第三个页面进入大厅，断言两个房间均以「旁观」入口展示。
  3. 点击乙场旁观，断言 URL 指向乙场且页面不含丙场文本。
  4. 复制一条预设得到第三份草稿，确认启动返回 429、业务码 `B0004`，草稿仍为 `DRAFT`。
  5. 等待乙场、丙场完成，再次确认第三份草稿返回 202 并最终完成。
- **预期**：容量上限严格为 2；拒绝不破坏草稿；终态释放槽位后可恢复确认。

### E03 直播结论

- **步骤**：
  1. 复用 E01 轨迹，在讨论运行中捕获结论面板。
  2. 第 3 条专家发言后，模型替身返回错误引文，触发提炼失败。
  3. 断言页面提示「观点更新暂缓，保留上次结果。」且旧结论文本仍在。
  4. 等待下一次提炼成功，断言提示消失、状态回到最新。
- **预期**：任何提炼失败都不得清空上一版结论；恢复后自动回到最新。

### E04 断线重连

- **步骤**：
  1. 乙场运行中，记录当前事件游标。
  2. 将浏览器上下文置为离线，等待后端事件继续增长至少 5 条。
  3. 恢复网络，等待自动重连；若进入「连接中断」，点击「恢复连接」。
  4. 断言页面出现离线期间最后一条发言文本。
  5. 刷新页面，等待终态，读取 SSE 回放。
- **预期**：游标补齐；事件序号连续且无重复；不出现其他房间内容。

### E05 故障与安全哨兵

- **步骤**：
  1. 通过 `/control` 注入 20 次阵容生成失败。
  2. 提交创建，断言 HTTP 502、页面出现错误提示、议题输入保留。
  3. 重置故障，再次提交，断言 201 并渲染 2 位专家。
  4. 使用非白名单 `Origin` 请求复制预设，断言 403 与 `B0006`。
  5. 断言前端源码、后端应用日志、浏览器请求与响应均不含注入的模型密钥。
- **预期**：失败可恢复；未授权来源被拒绝；密钥不进入前端与日志。

### E06 三视口

- **步骤**：
  1. 通过 API 创建并启动 2 专家房间。
  2. 分别以 1920×1080、1366×768、390×844 打开演播厅。
  3. 断言座位数 3、无横向溢出、主内容区纵向 `hidden`、成员列表 `auto`、无页面异常。
  4. 窄屏聚焦「现场」标签，按 `ArrowRight`、`End` 验证键盘切换。
  5. 终态后断言实录区 `auto` 滚动，点击引用定位到对应条目，并保存三张截图。
- **预期**：三视口内容完整；桌面与窄屏均保持内容区独立滚动。

### E07 预设与复制

- **步骤**：
  1. 读取预设列表，断言 6 条、slug 唯一、每条成员数为专家数 +1、主持人在首位且立场/视角为空。
  2. 同一预设连续复制两次，断言 201、ID 不同、议题相同、`DRAFT`、`lastEventSeq=0`。
  3. 断言复制前后模型上游调用次数不变。
  4. 断言两次复制的成员 ID 集合不相交。
- **预期**：复制只做数据投影，不触发模型；成员独立，不共享可变状态。

### E08 初始化幂等

- **步骤**：
  1. 创建空白目录，断言数据库文件不存在。
  2. 启动后端完成初始化，读取 6 条预设并记录指纹。
  3. 关闭后端，使用同一库再次启动，读取预设并比较指纹。
- **预期**：两次均为 6 条且指纹一致；初始化脚本可重复执行。

## 4. 通过标准

1. E01–E08 全部通过，且无跳过用例。
2. 失败时保留 trace、截图与日志，报告中记录实际失败断言。
3. 用例内不依赖真实模型输出文本，仅依赖本场标记与业务状态。
4. 测试结束后无残留 `java`、`vite`、模型替身进程；临时 SQLite 已删除。
